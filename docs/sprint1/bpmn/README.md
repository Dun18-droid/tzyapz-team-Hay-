# Моделі бізнес-процесів BPMN 2.0 (Спринт 1)

**Продукт:** «СтейНау» — бронювання готелів (`staynow`)  
**Виконавець (Інженер з тестування):** Андрущенко Костянтин

## Інструменти та формати
- **Редактор:** diagrams.net / draw.io (версія v24.7.17 / v24.x+)
- **Нотація:** BPMN 2.0 (Business Process Model and Notation)
- **Вихідні файли:** `.drawio` (векторний XML-формат діаграм)
- **Експорт:** `.png` високої роздільної здатності для швидкого попереднього перегляду

## Перелік змодельованих процесів

1. `01_booking` — **Бронювання номера**:
   - **Учасники:** Пул «Гість», пул «Готель» (доріжки «Система», «Адміністратор»).
   - **Логіка:** Клієнт заповнює форму; система проводить валідацію (`BookingValidator`); у разі помилки відправляється сповіщення і бронювання відхиляється; за валідних даних виконується підпроцес розрахунку вартості за сезонним тарифом `[+]` та перевірка зайнятості номера (зв'язок із `Data Store`); у разі зайнятості надсилається відмова; при доступності запускається паралельне виконання (шлюз AND): **«Зберегти бронювання в базі даних»** та **«Сформувати та надіслати підтвердження»**; після синхронізації адміністратор фіксує бронювання в панелі керування.
   - **Особливості BPMN:** Event-Based Gateway у пулі гостя, роздільні Message Catching Events підтвердження/відмов, кінцеві події для гілок помилок без висячих задач, зв'язок пулів через Message Flows.

2. `02_checkin` — **Заселення і виселення**:
   - **Учасники:** Пул «Гість», пул «Готель» (доріжки «Адміністратор», «Менеджер»), пул «Служба прибирання».
   - **Логіка:** Стартова подія заїзду за таймером; шлюз за подіями (**Event-Based Gateway**) розгалужує прибуття гостя або фіксацію неявки за дедлайном 20:00 (таймер No-Show); при явці перевіряються документи та видається ключ зі статусом «Заселено»; очікування виїзду за проміжним таймером (до 11:00); огляд номера адміністратором з формуванням об'єкта **`Картка гостя / Рахунок`** (`Data Object`); паралельно (шлюз AND) менеджер закриває рахунок і статус бронювання та надсилає квитанцію гостю, а адміністратор передає запит на прибирання; клінінг виконує підпроцес «Прибирання та дезінфекція номера» `[+]` та сповіщає про готовність; номер переводиться в статус «Доступний».
   - **Особливості BPMN:** Шлюз за подіями на старті, таймери, паралельні шлюзи AND, коректне відправлення квитанції від менеджера після закриття рахунку.

## Як відкрити та переглянути
1. **Онлайн-перегляд:**
   - Перейдіть на [app.diagrams.net](https://app.diagrams.net/).
   - Оберіть **File** -> **Open From** -> **Device...** і відкрийте файл `.drawio`.
2. **Локальний перегляд:**
   - Відкрийте за допомогою розширення **Draw.io Integration** у VS Code або diagrams.net Desktop.
3. **Швидкий перегляд:**
   - Відкрийте файли `.png` на GitHub або у будь-якому переглядачі зображень.
