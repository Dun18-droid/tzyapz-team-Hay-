### Description
S-20 вимагає автоматично завершувати сесію адміністратора через 30 хвилин неактивності, F-130 — вимагати повторний вхід після цього. Фактично після 31 хвилини без дій адмінпанель лишається доступною, повторний вхід не потрібен; тож залишена без нагляду відкрита сторінка дає стороннім повний доступ до керування номерами.
Severity Major: вимога безпеки не виконується, але бронювання гостями це не блокує. Priority P2: стосується захисту адмінського доступу і потребує виправлення до випуску, інші кейси не блокуються.

### Steps to reproduce
1. Відкрити у Chrome сторінку входу адмінпанелі /admin локального стенду.
2. У поле Username ввести admin, у поле Password ввести password, натиснути «Login». Відкривається розділ керування номерами; зафіксувати час входу.
3. Не виконувати жодних дій у вкладці 31 хвилину.
4. Натиснути «Rooms» у шапці адмінпанелі.

### Actual result
Після кроку 4 адмінпанель лишається відкритою: адреса /admin/rooms, показано список номерів 101–103 і кнопку «Logout». Сторінку входу не показано, повторний вхід не вимагається. Вхід о 15:09, натискання «Rooms» о 15:41 (25.10.2026).

### Expected result
Після кроку 4 відкрито сторінку входу /admin; для доступу до адмінпанелі потрібен повторний вхід (S-20, F-130).

### Environment
localhost, restful-booker-platform; адреса, коміт, версія Chrome і ОС — аркуш «Environment» у docs/sprint3/execution-log.xlsx (Run 1, 25.10.2026). Chrome, звичайне вікно (не інкогніто); обліковий запис admin / password (адміністратор); 15:09–15:41.
